# 02 — Frozen scorer as a pure function

**What to build:** The Frozen achievement scorer (Score formula v1, spec D5) as a
pure function: given a sequence of RAM snapshots it produces the Score plus a
full component breakdown (badges, events over the full range minus baseline and
museum-ticket bit, dex caught/seen, unique maps, capped level sum). The formula
carries a `score_version`. All components are running maxima of one-way game
bits; money is excluded.

**Blocked by:** 01 — v3 scaffold + Seam split.

**Status:** ready-for-human

- [x] Replaying a recorded RAM trace with known milestones moves the Score by the
      expected amounts per component
- [x] Repeatable actions do not move the Score: healing events, revisiting
      coordinates on one map, wild-battle grinding past the level cap
- [x] Skipping a gym is strictly worse than taking it (badge weight dominates)
- [x] The scorer emits the component breakdown alongside the scalar
- [x] Tests cover only external behavior (snapshots in → Score out), never
      internals

## Implementation notes (2026-09-11)

- Scorer: `v3/frozen/scorer/` (`core.py` pure function `score_snapshots`,
  `SCORE_VERSION = "1.0.0"`, `ScoreResult` with component breakdown,
  `load_baseline`). No pyboy/env imports — pure over bytes.
- Snapshot format: contiguous WRAM window `SNAPSHOT_BASE=0xD163` …
  `SNAPSHOT_END_INCLUSIVE=0xDA45` (2275 bytes), constants in
  `v3/frozen/ram_map.py`. Window doubles as the telemetry contract for issue 03
  (includes x/y, map, badges, events, dex, levels, play clock).
- New ram_map entries verified against ~/dev/pokered: wPokedexOwned
  0xD2F7–0xD309, wPokedexSeen 0xD30A–0xD31C, NUM_POKEMON=151, NUM_MAPS=0xF8,
  wPlayTime* 0xDA41–0xDA45. Museum ticket bit confirmed LSB of 0xD754 via the
  `bit (\1) % 8, a` macro in pokered's events.asm.
- Frozen baselines: `v3/frozen/scorer/baselines/*.bin` + manifest.json
  (sha256-checked), generated by `v3/verify/generate_event_baselines.py` from
  the 4 root save states (init/fast_text_start: 0 event bits; has_pokedex/
  has_pokedex_nballs: 11).
- Fixtures: `v3/verify/capture_scorer_fixtures.py` → `v3/tests/fixtures/`
  (snapshots.bin + meta.json per scenario). Deliberate deviation from the
  Testing Decisions wording: v2 never persisted RAM, so "real v2 runs" were
  replaced by real save-state captures + synthetic RAM pokes starting from real
  states. The capture script computes expected values with its own independent
  logic (never importing the scorer) so the tests cross-validate two
  implementations instead of being tautological.
- Tests: `v3/tests/test_scorer.py` (pytest, first test suite in the repo;
  pytest installed into `.venv`). 11 tests, all green; fixtures are pure data,
  no pyboy at test time. Both generators re-run byte-identical
  (reproducibility verified).
